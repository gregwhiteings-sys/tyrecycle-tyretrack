FULL FIELD-OF-VIEW CORRECTION

The earlier compression build requested a 640x360 centre crop of the 1080p
ISP image. That also narrowed the derived live preview and AI image. This
version first scales the complete 1920x1080 ISP image by 1/3 to 640x360,
then uses the entire result for video, preview and detection. No camera
repositioning or compensating count-line adjustment should be needed.
Verify the restored view against the previous wide view after rebuilding.
Live hardware validation is still needed.

OAK VIDEO COMPRESSION UPDATE

Upload the extracted source files to the existing GitHub repository, including
requirements-windows.txt, .github/workflows/windows-portable.yml, oak_recording.py,
oak_recording_test.py and test_data/oak_h264_sample.h264. Run the existing action:
TyreTrack Windows Portable (OAK Onboard AI).

The portable build includes PyAV and its native FFmpeg libraries. No separate
FFmpeg or Python install is required on the production PC.

In CAMERA, enable Record OAK video (MP4). H264 compression now runs on OAK.
PC saves 640x360 / 15 FPS recordings at a target 1.5 Mbps, then stream-copies
into MP4 at segment close. No PC decoding/re-encoding is used for recording.
Segments rotate at the first keyframe after 15 minutes. The current recording
is a .h264 file until the segment closes (or recording is stopped).
MP4 finalisation failure keeps the .h264 source for recovery.

Preview and detection paths, detector weights, tracking IDs, count line and
reports are unchanged. Preview still uses uncompressed images. This change
reduces recording encoding work; it does not guarantee smoother preview or
resolve every camera/network pause. An extra compressed recording stream is
sent over Ethernet, alongside the existing preview and AI images.

Recording remains opt-in. A new segment waits for a keyframe (normally within
one second). Missing encoded packets close the segment; recording waits for
the next keyframe so corruption does not propagate. Such gaps are logged.
A power failure can leave the active .h264 file; it is not yet an MP4.

Validation completed locally: real DepthAI 2.30 pipeline construction; playable
MP4 decoding; keyframe segmentation; packet loss recovery; enable/disable;
source preservation after remux failure; independent preview/AI matching;
GUI labels and below-5 flashing. Full Windows source and portable smoke tests
run in GitHub. Live encoder behaviour and counting still require OAK testing.

On site: check a short recording, stop recording to finalise it, play the MP4,
then compare processing FPS and CPU with the prior build and check 100 tyres.
Send data/tyretrack.log if the encoder or recording reports a fault.

Foreign-object detection/tracking has NOT moved to OAK in this update.
